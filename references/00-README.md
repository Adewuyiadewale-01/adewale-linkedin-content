## Files

1. [Strategy](01-adewale-strategy.md): positioning, audience, objectives, subject territory, and confirmed strategic decisions.
2. [Voice Guide](02-adewale-voice-guide.md): tone, formatting, stylistic influences, drafting principles, approved evidence, and anti-patterns.
3. [Content System](03-adewale-content-system.md): subject areas, post formats, idea sources, structures, and idea-development process.
4. [Content Log](04-adewale-content-log.md): published-post record, experiments, results, qualitative outcomes, and lessons.

## Routing Rules

| Task | Required context |
| --- | --- |
| Write or revise a post | Strategy + Voice Guide + relevant Content System format |
| Generate content ideas | Strategy + Content System |
| Review a proposed topic | Strategy + Content System |
| Review tone or formatting | Voice Guide |
| Review performance | Strategy + Content Log |
| Update LinkedIn positioning | Strategy |
| Turn performance into a new rule | Content Log first, then update the relevant canonical file after Tony approves |

Do not load the entire system when a smaller combination is sufficient. The files together are the source of truth; this index only routes work and must not duplicate their full contents.

## Update Protocol

- Preserve confirmed facts unless Tony changes them.
- Put each rule in one canonical file to prevent conflicts.
- If Tony explicitly states that a preference or decision is permanent, record it directly.
- If a new instruction merely suggests a reusable preference, tell Tony what was inferred and ask whether it should become a standing rule.
- Do not turn a one-post instruction into a universal rule.
- Add approved writing examples to the Voice Guide with the reason they work.
- Record publication results and experiments in the Content Log before generalizing from them.
- Do not treat one successful post as permanent proof of a strategy.
- No separate task manager is needed at this stage.
